# 本地记忆管理

## 流程

1. 先读根 `AGENTS.md` 和 `重要记忆/00_AI阅读入口.md`。
2. 创建或整理具体文件时读 [模板](references/templates.md)；新建或实质修改正式结构化记忆时读 [统一 Schema](references/memory-schema.md)。
3. 按主事实入口回源，不用首读摘要替代源文件。
4. 先保留原件，再更新事实、状态、索引和首读压缩；把相关写回作为一个事务验收。
5. 完成前读 [验收说明](references/validation.md)，运行只读验证器并人工复核来源、授权与隔离边界。

## 核心边界

- 普通任务不静默写回；只有明确维护、项目/日期资产更新或高价值真实事故才写回。
- Inbox 原件不覆盖；正式写回、索引、处理件状态、移动和验收全部成功后才算入库。
- 用户画像不保存操作配置；秘密、登录态、浏览器 Profile、缓存和可重建依赖不进入库。
- 全库遍历必须在进入目录前剪枝，排除范围以根 `AGENTS.md` 为准。
- 新文件采用 Schema；历史文件在实质触碰时渐进迁移，不批量伪造字段。
- 同一规则、状态或索引只维护一个权威来源，派生入口只提示和回链。
- 项目专用 Skill 只同步项目 README 与项目索引；未经用户明确确认，不进入全局技能入口。
- 项目排序使用 README 显式“最后更新”；不使用文件系统 mtime。
- 董事会是独立隔离系统：普通任务不得读取或建议启动；只有用户说出“启动董事会决策”时按 `董事会/运行内核.md` 运行，明确维护时才读取维护文件。成员 Skills 不进入普通技能索引，历史决策只有用户明确要求记录时才写入。

## 写回顺序

1. 保留或归档原始资料。
2. 更新正式事实文件和公共元数据。
3. 更新项目状态、日期索引或目录索引。
4. 只在跨场景高频且会改变下一步时更新首读压缩。
5. 检查链接、表格、Schema、编码、安全边界和机器验收。
