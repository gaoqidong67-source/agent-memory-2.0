# Inbox

本目录是文件进入长期记忆前的事务流转区。原件不覆盖，`临时文件/` 与长期入库流程隔离。

## 四个文件区

| 目录 | 保存内容 | 边界 |
| --- | --- | --- |
| `未处理文件/` | 长期候选原件；按六类预分类 | 不改写、不删除 |
| `已处理文件/` | 原件与带 SHA256、标签和状态的 Markdown 处理件 | 短期待入库队列 |
| `已入库文件/` | 已完成正式写回和验收的原件与处理件 | 默认只读 |
| `临时文件/` | 一次明确任务的参考材料 | 不建处理件、不入库、不自动删除 |

`未处理文件/` 固定保留 `日常记忆/`、`知识点/`、`提示词/`、`工具/`、`技能/`、`其他待判断/`。用户预分类默认得到保留；内容明显冲突或会造成错误入库时，先确认再改类。

## 流程

```text
保留原件
-> 计算 SHA256 并创建忠实 Markdown 处理件
-> 原件与处理件进入已处理文件
-> 用户明确要求“整理记忆库”
-> 写入正式事实与索引
-> 验收
-> 更新处理件为已入库并移动到已入库文件
```

任一步失败时不得提前移动。收尾时清理未处理/已处理队列中的空批次目录，但保留固定预分类入口。`临时文件/` 不参与以上流程，未经明确删除指令始终保留。

## 处理件最小元数据

```yaml
---
title: 原文件标题
status: 已处理
source_file: 原文件名.ext
source_type: 文件类型
source_sha256: SHA256
processed_at: YYYY-MM-DD HH:mm:ss
ingested_at:
tags: [inbox, 待入库]
memory_targets: []
---
```

正文忠实保留原始顺序；OCR、转写和结构提取必须标为衍生内容，不能冒充原文。
